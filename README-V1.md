# 算力调度运营平台 (Compute Power Dispatching Operation Platform)

## 平台概述

本平台为全国一体化算力网络体系下的核心业务载体，定位为面向多端用户的前端展示与后台管理综合型系统。平台提供算力资源展示、智算产品交易、政策聚合查询、供给方服务入驻，以及深度的控制台管理与费用中心账单运营功能。

系统前端架构基于 `Vue 3 (Composition API)` 构建，采用 `TypeScript` 提供强类型保障，结合 `Vite` 实现极速构建。UI 交互层深度融合 `Element Plus` 组件库，数据流转及网络通信由 `Pinia` 与 `Axios` 驱动。

---

## 工程架构演进路径

系统底层架构经历了从基础静态呈现到企业级工程标准的深度重构，整体演进路径分为以下五个关键阶段：

### 阶段零：安全底座与鉴权隔离 (RBAC 机制)

废弃早期基于本地明文标识判断登录状态的越权隐患，全面重构验证体系。引入基于 JWT (JSON Web Token) 的身份校验方案。重构路由表，将前台公共页面与后台控制台（及费用中心）进行物理隔离。依托全局路由前置守卫拦截访问请求，动态解析权限标识并挂载私密路由，确立基于角色的访问控制（RBAC）基础。

### 阶段一：全局状态集中化与持久化

消除基于原生 `window.dispatchEvent` 事件广播机制及直接操作 `localStorage` 带来的数据耦合与状态同步异常问题。引入 `Pinia` 作为唯一状态源，分别建立独立的购物车模型与用户消息模型。结合状态持久化插件，保障关键业务数据在浏览器刷新周期内的完整性与一致性。

### 阶段二：API 工程化与网络通信解耦

彻底剥离原先混杂在视图组件内部的 Mock 数据生成与原生定时器模拟逻辑。构建专用的网络请求调度层，统一封装 Axios 实例。建立请求拦截器以自动注入鉴权令牌，建立响应拦截器以全局接管错误处理与 401 状态重定向。业务数据请求下沉至独立的 API 模块进行管理。

### 阶段三：TypeScript 强类型化与巨型视图瘦身

制定全局数据实体类型接口（如 `ComputingProduct`），大范围清除代码库中的 `any` 类型定义，恢复静态编译期的类型推导与错误预警能力。针对体积过大、职责过载的核心布局文件进行结构拆分，提取并封装出高内聚的原子化独立组件（如导航顶栏、全局抽屉等），极大降低视图层代码复杂度。

### 阶段四：健壮性加固与样式规范归一

针对所有涉及数据提交与状态变更的交互节点，注入精确到行级别的并发锁定（Loading 态）与防抖机制，杜绝脏数据产生。抽象系统散落的硬编码色值与边框属性，统一沉淀为全局 CSS 变量池，在维持视觉呈现绝对一致的前提下，为系统后续的主题定制与暗黑模式适配奠定底层规范。

## 核心源码结构与文件说明

以下为当前系统工程核心目录及关键文件的详细剖析。在后续系统迭代与维护中，需严格遵循其文件职责划分。

### 1. 工程配置层 (根目录)

* **`package.json` / `package-lock.json**`
* **作用**：定义工程元数据、构建脚本指令（`dev`, `build` 等），并严格锁定所依赖的第三方 NPM 包的版本号。
* **注意点**：生产环境部署时，依赖安装必须以 `lock` 文件为准，严禁随意升级核心库大版本。


* **`vite.config.ts`**
* **作用**：Vite 构建工具的核心配置文件。配置了路径别名（`@` 指向 `src`）、代理转发，并集成了组件自动按需导入（`unplugin-auto-import`）插件。
* **注意点**：若增加新的全局自动引入规则，需在此文件及对应的 `.d.ts` 声明文件中同步更新。


* **`tsconfig.*.json`**
* **作用**：TypeScript 编译指导规则。按照职责拆分为应用程序域代码检查（`tsconfig.app.json`）与构建脚本域检查（`tsconfig.node.json`）。
* **注意点**：配置文件内已开启严格的变量未使用检测与扩展名导入检测，编写业务逻辑时需维持代码的严谨性。



### 2. 源码逻辑层 (`src/` 目录)

#### 2.1 框架入口与全局抽象

* **`main.ts`**
* **作用**：系统运行主干。负责挂载 Vue 应用实例，注册路由、状态管理、UI 组件库，并引入全局统一样式。


* **`App.vue`**
* **作用**：顶级根视图容器。所有页面的路由插座（`<router-view>`）均挂载于此。


* **`assets/styles/theme.css`**
* **作用**：全局主题样式池。集中管理各类背景、文本、边框与高亮颜色的 CSS 变量（以 `--pc-` 为前缀）。
* **注意点**：新增页面或组件时，严禁使用十六进制（如 `#1677FF`）硬编码色值，必须调用此文件内的标准变量。



#### 2.2 核心网络通信 (`api/` 与 `utils/`)

* **`utils/request.ts`**
* **作用**：网络通信枢纽。提供实例化的 Axios 对象，并统筹所有出入口报文的拦截与状态码分发。


* **`api/` (如 `auth.ts`, `market.ts`)**
* **作用**：业务网络接口集散地。视图组件仅需调用此处暴露的函数，无需关心底层通信细节。
* **注意点**：请求参数与返回值必须标注明确的 TypeScript 类型接口。



#### 2.3 全局状态仓库 (`store/`)

* **`index.ts`**
* **作用**：Pinia 实例创建与持久化插件挂载。


* **`modules/cart.ts`**
* **作用**：购物车域状态模块。管理已选资源列表、数量及价格派生计算，管控侧边抽屉的启停。


* **`modules/user.ts`**
* **作用**：用户域状态模块。统筹系统未读消息统计，并处理跨标签页的消息同步广播。
* **注意点**：状态模块均启用了本地持久化存储（LocalStorage），设计新状态时需甄别是否需要加入 `pick` 白名单进行缓存。



#### 2.4 数据类型规范 (`types/`)

* **`index.ts`**
* **作用**：静态业务模型的定义中心。例如核心资源实体（`ComputingProduct`）、系统消息实体（`MessageItem`）等。
* **注意点**：数据模型变更（如后端接口增减字段）必须优先在此文件同步，以触发全局静态类型检查。



#### 2.5 视图骨架与可复用组件 (`layout/` 与 `components/`)

* **`layout/`**
* **作用**：定义多页面的宏观排版骨架。包含独立的前台总布局（`index.vue`）、控制台框架（`ConsoleLayout.vue`）与财务结算框架（`FinanceLayout.vue`）。
* **注意点**：使用 Element Plus 容器时，为避免组件拆分引发的 flex-direction 默认值异变，容器层需显式声明 `direction="vertical"`。


* **`components/FrontHeader.vue`**
* **作用**：从宏观布局中抽离的顶部导航及身份功能面板。配合 `position: sticky` 实现吸顶效果。


* **`components/CartDrawer.vue`**
* **作用**：全局悬浮的购物车结算抽屉，被统一放置于根布局边缘，通过 Pinia 指令激活。


* **`components/SeamlessScroll.vue`**
* **作用**：高度定制化的无缝轮播组件。
* **演进记录**：针对原首页直接使用原生轮播存在的重型渲染卡顿与轨道宽度塌陷问题，特引入此组件进行底层 DOM 结构干预与 CSS 动画优化，实现长列表的平滑无缝循环。



#### 2.6 页面业务逻辑 (`views/`)

* **`Login.vue`**：独立鉴权入口。负责采集凭证，调用 Auth API 获取令牌，建立用户会话后进行路由回调。
* **`home/`**：门户展示控制中心。统筹多模块横幅及业务指引静态渲染。
* **`market/`**：智算产品核心交易场。内置高复杂度多维交叉检索逻辑，承载大量卡片渲染与异步翻页加载（带骨架屏屏障机制）。
* **`solution/`, `policy/`, `provider/**`：系统外围信息专区。处理行业解决方案呈现、政策文档查阅与企业入驻表单的校验流转。
* **`console/` 与 `finance/**`：核心后台管理模块体系。处理计算资源生命周期管理、退订续费、工单流转以及资金账务清算。

#### 2.7 路由管控枢纽 (`router/`)

* **`index.ts`**
* **作用**：系统页面寻址的地图与门禁。将公共路由（`constantRoutes`）与鉴权路由（`asyncRoutes`）分别定义。
* **注意点**：任何新建的私有后台页面均应注册于鉴权路由表中。全量请求均须受路由前置守卫（JWT 有效性验证与拦截）的监察。

## 环境部署与运行指南

本系统需基于 Node.js 运行环境进行构建。建议使用 LTS（长期支持）版本。

### 本地开发调试

在项目根目录拉取依赖库并启动本地开发服务器：

```bash
npm install
npm run dev

```

### 生产环境编译

执行类型安全校验及高强度体积压缩，打包生产环境所需的静态只读资产：

```bash
npm run build

```

编译完成后，根目录将产出 `dist` 文件夹，包含最终的 HTML/CSS/JS 资源。

### 服务器托管要求

1. 构建产物具备高度静态化特征，可直接依托 Nginx、Apache 或是现代边缘网络（如 Vercel, Cloudflare Pages）进行托管。
2. 鉴于系统采用了 `Vue Router`，若使用 Nginx 服务器物理托管，务必于配置代理块中追加下述重定向回退策略，以确保用户执行页面强制刷新时路由寻址正常：
```nginx
location / {
  try_files $uri $uri/ /index.html;
}

```
